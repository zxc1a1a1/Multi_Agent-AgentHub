# AI Collaboration Workflow Contract

## 1. 契约目的

本文定义 AgentHub 项目中 AI 编程代理参与开发时的协作契约。

本契约用于保证：

- 任务范围清晰；
- 上下文选择可控；
- 串行 Skill 重构不越界；
- 文档和代码边界明确；
- 文件包交付可复用；
- Review 和交接可追溯。

## 2. 核心原则

- 用户当前指令优先。
- 当前阶段由用户指定的 Sprint / Plan / 任务决定。
- 历史 MVP 规则不能自动成为当前限制。
- 一个任务尽量只处理一个问题域。
- 串行 Skill 生成时，每轮只处理一个 Skill。
- 文档任务默认不生成业务代码。
- 文件包必须包含清单和补丁说明。
- 中文项目默认输出中文。

## 3. 标准流程

```text
任务接收 → 上下文扫描 → 范围锁定 → 计划制定 → 执行修改 → 验证 → Review → 交接
```

## 4. 上下文选择

AI 应按以下顺序选择资料：

1. 用户本轮明确给出的文件、链接、目录或 Skill；
2. 用户上传的 Sprint / PDR / Contract 文件；
3. 当前任务直接涉及的最小文件集合；
4. 必要时再说明需要额外资料。

不得一次性读取或修改所有 Skill。

## 5. 串行 Skill 重构

串行 Skill 重构时：

- 只处理用户指定 Skill；
- 不自动生成后续 Skill；
- 不大量引用其他 Skill；
- 保持当前 Skill 独立可读；
- 必要 references 只补充当前 Skill；
- 交付包只包含当前 Skill 及其直接契约文件。

## 6. 文件包交付

文件包必须包含：

```text
.claude/skills/{skill-name}/SKILL.md
.claude/skills/{skill-name}/references/*.md
docs/contracts/{related}.md
PATCH_NOTES.md
MANIFEST.md
```

实际文件以任务需要为准。

文件包不得包含：

- 缓存；
- 构建产物；
- 无关业务代码；
- 密钥；
- 私密配置。

## 7. 验证

文档包至少验证：

- 文件路径；
- Markdown 结构；
- frontmatter；
- 中文一致性；
- 独立性；
- 是否越界；
- 是否缺少清单或补丁说明。

代码任务应尽量验证测试、类型检查、构建或 smoke test。

## 8. 完成标准

一个 AI 协作任务完成需要满足：

- 用户目标已覆盖；
- 范围未越界；
- 输出格式符合用户要求；
- 交付物可定位；
- 有变更说明；
- 有使用方式；
- 明确未包含内容；
- 如未运行测试，已说明。
