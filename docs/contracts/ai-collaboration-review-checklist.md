# AI Collaboration Review Checklist

## 1. 用户目标

- [ ] 是否理解用户本轮真正目标？
- [ ] 用户要的是思路、文件包、代码修改还是 Review？
- [ ] 是否按用户要求使用中文？
- [ ] 是否按用户要求串行处理？

## 2. 范围

- [ ] 是否只处理指定 Skill / 文件？
- [ ] 是否没有顺手修改其他 Skill？
- [ ] 是否没有生成未授权业务代码？
- [ ] 是否没有改动部署、数据库、前端或后端代码？

## 3. 阶段

- [ ] 是否正确识别当前阶段？
- [ ] 是否没有把 MVP 历史规则当成当前限制？
- [ ] 是否没有把 Sprint 示例写成永久硬约束？
- [ ] 是否没有把长期规划写成当前必做？

## 4. 独立性

- [ ] `SKILL.md` 是否独立可读？
- [ ] 是否避免依赖其他 Skill 才能理解？
- [ ] references 是否只补充当前 Skill？
- [ ] 是否没有复制大量其他 Skill 规则？

## 5. 文件包

- [ ] 是否包含 `MANIFEST.md`？
- [ ] 是否包含 `PATCH_NOTES.md`？
- [ ] 是否使用仓库相对路径？
- [ ] 是否文件名清晰？
- [ ] 是否不包含缓存和构建产物？
- [ ] 是否不包含秘密信息？

## 6. 质量

- [ ] frontmatter 是否标准？
- [ ] Markdown 标题是否清晰？
- [ ] 中文是否一致？
- [ ] 示例是否明确为示例？
- [ ] 禁止事项是否清楚？
- [ ] 完成定义是否可验证？

## 7. 交接

- [ ] 是否提供下载链接？
- [ ] 是否列出包内文件？
- [ ] 是否说明主要变化？
- [ ] 是否说明如何使用？
- [ ] 是否说明未包含内容？
- [ ] 是否没有承诺后台继续工作？
