# AgentHub 新架构 Contract / Skill 更新指导文件

## 本包目的

把 contract 和 skill 的事实源统一切到重构计划：

```text
pkg/adk
pkg/runtime
services/gateway
services/orchestrator
services/agents/*
frontend
```

PDR 只保留产品目标，不再作为工程目录、服务边界、协议细节的主依据。

## 先改什么

推荐提交顺序：

1. 复制本包 `replacements/` 到仓库根目录。
2. 提交 contract/skill 更新。
3. 把 `postgres-schema.md`、`redis-usage.md`、`object-storage-policy.md` 移到 `docs/contracts/_legacy/`。
4. 修复代码阻塞：`SQLSessionService.GetOrCreate`。
5. 清理 `go.work` 中的旧 `./server`、`./agents`。
6. 将默认 compose 切到新架构六服务拓扑。
7. 补 Runtime Agent Factory 和 memory session。
8. 再处理 Gateway↔Orchestrator gRPC 迁移。

## 不建议一次删除什么

不要在同一个提交里删除旧 `server/`、旧 `agents/` 代码目录。先通过 contract/skill 标记 legacy，再单独做代码迁移提交。

## 关键口径

- `/agui/runs` 是正式 Gateway run 入口。
- `/api/chat` 只是临时兼容/demo 包装。
- Gateway↔Orchestrator 的目标是 gRPC streaming。
- HTTP/SSE internal API 是临时兼容，不是目标合同。
- MySQL 是目标持久化。
- SQLite 是 demo/profile-only。
- `pkg/adk` 不放 Provider、不放业务、不放 YAML 解析。
- `pkg/runtime` 放 Provider、Config、Registry、Session、Skill、AG-UI Translator。

## Review 时重点看

- skill 是否还让 worker 改 `server/internal/*` 或旧 `agents/*`。
- contract 是否还把 PDR 的 PostgreSQL/Redis/Object Storage 当当前事实。
- docker contract 是否还指向旧 `./server`、`./agents`。
- frontend contract 是否允许直接调用 Orchestrator/Agent。
- gateway-orchestrator contract 是否把 HTTP/SSE 当目标协议。
