# 变更报告模板

生成文件包或补丁时，建议使用以下模板。

```md
# PATCH_NOTES

## 1. 本次目标

说明本次为什么修改。

## 2. 修改范围

列出替换、新增、未修改的文件。

## 3. 主要改动

用 5-10 条说明核心变化。

## 4. 设计取舍

说明为什么这样处理。

## 5. 未包含内容

说明没有包含业务代码、没有修改其他 Skill 等。

## 6. 验证方式

说明做了哪些静态检查或测试。

## 7. 使用方式

说明如何解压、复制或查看 diff。

## 8. 后续建议

列出可选下一步，不主动执行。
```

## 要求

- 必须中文；
- 必须清楚；
- 必须能让开发者知道文件包如何使用；
- 不得夸大已完成事项；
- 不得声称运行了未运行的测试。
