# 范围控制规则

## 1. 基本原则

AI 必须按用户本轮指定范围工作。

范围优先级：

1. 用户当前消息；
2. 用户本轮上传或指定的文件；
3. 当前对话已有明确共识；
4. 仓库现有结构；
5. 历史计划或旧 Skill。

如果旧 Skill 和当前用户目标冲突，以当前用户目标为准。

## 2. 串行 Skill 场景

当用户说“一个一个改”或指定某个 Skill 时：

- 只处理该 Skill；
- 不主动生成下一个 Skill；
- 不顺手改其他 Skill；
- 不把其他 Skill 作为必读依赖；
- 可以在交接中提示后续应改哪个，但不执行。

## 3. 文档任务范围

文档任务默认允许：

- 当前 Skill 的 `SKILL.md`；
- 当前 Skill 的 `references/*.md`；
- 与当前 Skill 直接对应的 `docs/contracts/*.md`；
- `PATCH_NOTES.md`；
- `MANIFEST.md`。

文档任务默认不允许：

- 业务代码；
- Docker；
- SQL；
- 前端组件；
- 后端 handler；
- CI 配置。

## 4. 当前阶段规则

不得把 MVP 历史规则当成当前限制。

当前阶段由用户本轮指定的 Sprint / Plan / 任务决定。

## 5. 示例不是硬约束

如果文档中出现示例 Agent、示例服务、示例路径，必须避免写成唯一允许项。
